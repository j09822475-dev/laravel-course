# Android

Тренажёр ставится на телефон двумя способами: готовым APK (лежит рядом,
собирается одной командой) и как PWA прямо из браузера.

## APK

```sh
./build-apk.sh          # на выходе build/trainer.apk
```

Сборка идёт **без Android Studio, Gradle и Google SDK** — только на
инструментах из пакетов дистрибутива, потому что `dl.google.com` бывает
недоступен:

```sh
sudo apt-get install -y aapt apksigner zipalign dalvik-exchange \
     android-sdk-platform-23 android-sdk-build-tools
```

Что делает скрипт: `aapt2` собирает ресурсы и генерирует `R.java`, `javac`
компилирует исходники против `android.jar`, `dalvik-exchange` превращает
классы в `classes.dex`, `aapt` кладёт его в пакет, `zipalign` выравнивает,
`apksigner` подписывает. Отладочный ключ создаётся при первом запуске в
`keystore/` и в репозиторий не попадает.

### Установка на телефон

1. Перенесите `build/trainer.apk` на телефон (кабель, облако, мессенджер).
2. Откройте файл и разрешите установку из этого источника — Android
   спросит, потому что APK подписан отладочным ключом, а не ключом
   Google Play.
3. При первом запуске приложение спросит адрес сервера, на котором
   развёрнут тренажёр.

### Что это за приложение

Тонкая нативная оболочка (WebView) над вашим сервером: тренировка,
прогресс и аккаунт остаются на сервере, поэтому второй кодовой базы и
рассинхронизации не возникает. Внутри — сохранение cookie-сессии между
запусками, переход «назад» по истории, открытие внешних ссылок в браузере,
понятный экран при обрыве связи и смена адреса сервера с того же экрана.

### Куда указывать адрес

- **Сервер в интернете:** `https://ваш-домен` — обычный рабочий сценарий.
- **Ноутбук в той же сети Wi-Fi:** запустите `php artisan serve --host=0.0.0.0`
  и укажите `http://192.168.X.X:8000`. Открытый HTTP работает, потому что
  приложение собрано с `targetSdkVersion 23` — ограничение на нешифрованный
  трафик появилось в API 28.

### Ограничения этой сборки

- `targetSdkVersion 23` — это максимум, который даёт `android.jar` из
  пакетов дистрибутива. Для установки вручную подходит (Android 14 требует
  минимум 23), но **Google Play требует 34+**, поэтому для публикации в
  магазине нужен настоящий Android SDK — см. раздел про TWA ниже.
- Подпись отладочная. Для магазина нужен собственный ключ, и терять его
  нельзя: без того же ключа обновление не загрузить.
- APK собран и проверен статически (подпись `apksigner verify`, разбор
  манифеста через `aapt dump badging`, наличие классов в `classes.dex`).
  Запустить его на устройстве в среде сборки было негде — эмулятор
  поставляется только из закрытого `dl.google.com`, так что первый запуск
  на вашем телефоне и есть настоящая проверка.

## PWA (без установки APK)

Приложение остаётся устанавливаемым PWA: откройте сайт в Chrome на телефоне
и выберите «Установить приложение». Манифест, service worker и иконки лежат
в `public/`, условия установки закреплены тестом `tests/Feature/PwaTest.php`.

## Публикация в Google Play (TWA)

Для магазина удобнее Trusted Web Activity — та же обёртка, но с проверкой
владения доменом, без адресной строки и с поддержкой свежих API:

```sh
npm install -g @bubblewrap/cli
bubblewrap init --manifest https://ВАШ-ДОМЕН/manifest.webmanifest
bubblewrap build
```

Отпечаток ключа из `bubblewrap fingerprint list` и имя пакета пропишите в
`public/.well-known/assetlinks.json` — по этому файлу Android убеждается,
что приложение и сайт принадлежат одному владельцу. Этот путь требует
доступа к `dl.google.com` и в среде разработки проекта не проверялся.

## Нативный клиент на API

Если понадобится полноценное нативное приложение (офлайн-очередь ответов,
уведомления о повторениях, запись голоса), сервер готов: `routes/api.php`
отдаёт токены Sanctum и весь цикл тренировки. Список эндпоинтов — в
корневом `README.md`.

# Laravel Interview Trainer

Тренажёр для подготовки к скринингу и техническому собеседованию на позицию
**full stack Laravel developer**. Приложение проводит вас через реальный сценарий найма:
разговор с рекрутером → техническая секция → живое кодирование → разбор ответов,
а затем возвращает проваленные вопросы по расписанию интервальных повторений.

Сам тренажёр написан на Laravel — его код можно читать как пример того,
о чём спрашивают на собеседовании: сервисы и контейнер, enum'ы, миграции,
Blade-компоненты, feature-тесты и консольная команда.

## Что внутри

**147 вопросов в 12 темах** с эталонными ответами, уточняющими вопросами интервьюера,
чек-листами оценки и красными флагами:

| Тема | Что проверяет |
| --- | --- |
| PHP и ООП | типы, память, генераторы, PHP 8.x, Composer, FPM и opcache |
| Ядро Laravel | жизненный цикл запроса, контейнер, middleware, очереди, кэш, планировщик |
| Eloquent и работа с данными | связи, N+1, транзакции, миграции без даунтайма |
| SQL и базы данных | индексы, планы запросов, уровни изоляции, Redis, масштабирование |
| API, HTTP и безопасность | REST, Sanctum/Passport, политики, OWASP, вебхуки |
| Frontend для fullstack | JS и event loop, Blade, Livewire, Inertia/Vue, Vite, Web Vitals |
| Тестирование | feature против unit, фейки, моки, CI, работа с легаси |
| Архитектура | SOLID, паттерны, системный дизайн, рефакторинг |
| Деплой и эксплуатация | релизы без простоя, Docker, git-процесс, поведение в инциденте |
| HR-скрининг и софт-скиллы | рассказ о себе, зарплата, конфликты, вопросы работодателю |
| Живое кодирование | задачи на код, ревью чужого кода, SQL, схема БД |
| Английский на собеседовании | speaking-практика, речевые блоки, шэдоуинг, упражнения с пропуском |

### Режимы тренировки

- **Скрининг (30 минут)** — знакомство, база по PHP и Laravel, пара практических вопросов.
- **Техническое интервью (60 минут)** — углублённая теория, живое кодирование, системный дизайн.
- **Блиц-тест** — вопросы с вариантами ответов и автоматической проверкой.
- **Карточки и повторение** — проработка слабых тем; вопросы, которые вы провалили, возвращаются первыми.
- **Интервью на английском** — отдельный сценарий: разогрев речи, самопрезентация, техническое
  объяснение по-английски и отработка речевых блоков.

Любой сценарий, кроме последнего, можно пройти на английском — переключатель языка есть на главной,
а в банке вопросов у каждого вопроса свои кнопки RU / EN.

### Как считается прогресс

- После каждого открытого вопроса вы **честно оцениваете свой ответ** (не знал / плавал / ответил / уверенно);
  вопросы с вариантами ответов проверяются автоматически.
- Оценка идёт в планировщик повторений (упрощённый SM-2): провал возвращает вопрос сегодня,
  уверенный ответ отодвигает его на дни и недели.
- **Готовность к собеседованию** = 70% качество ответов + 30% охват банка вопросов,
  поэтому «знаю три темы идеально» не даёт высокий процент.
- В отчёте по сессии — разбор каждого ответа, эталон рядом с вашим, и рекомендации,
  включая вопросы, на которых вы заметно превысили ориентировочное время.

Профиль кандидата создаётся автоматически и живёт в сессии браузера — регистрация не нужна.

## Английский

Скрининг часто идёт на английском, поэтому язык тренируется тремя способами.

**1. Тема «Английский на собеседовании»** — 24 задания в трёх форматах:
speaking-вопросы с модельными ответами (расскажите о себе, объясните архитектуру,
объясните N+1 нетехническому человеку, зарплатные ожидания), шэдоуинг-блоки для
проговаривания вслух с разметкой пауз и ориентиром по темпу, и упражнения с
пропуском на речевые связки (I was ___ for the payment module).

**2. Переключатель языка у всех вопросов.** Каждый из 147 вопросов имеет английскую
версию: формулировка и модельный ответ в разговорном регистре — короче русского
разбора, потому что вслух на собеседовании вы говорите 60–90 секунд, а не читаете
эссе. Если перевода нет, показывается оригинал с пометкой, а не пустой экран.

**3. Режим «Интервью на английском»** — сценарий из пяти фаз: разогрев речи
шэдоуингом, самопрезентация, три технических вопроса по-английски, отработка фраз
и финальный вопрос. В отчёте появляются языковые рекомендации: какие блоки не
вспомнились и не пора ли сокращать ответы.

### На каких методиках это построено

Приёмы выбраны по доказанной эффективности, у каждого есть конкретная реализация:

| Приём | Что это даёт | Где в тренажёре |
| --- | --- | --- |
| Активное вспоминание | извлечение из памяти закрепляет лучше перечитывания | эталон открывается только после вашего ответа |
| Распределённые повторения | интервалы удерживают материал дольше зубрёжки | планировщик SM-2, провал возвращает вопрос сегодня |
| Тестирующий эффект | проверка знания сама по себе обучает | блиц-тесты с автопроверкой |
| Эффект генерации | слово, которое достали сами, помнится лучше узнанного | упражнения с пропуском, ответ вписывается руками |
| Чанкинг | готовый речевой блок достаётся за один шаг | связки вместо отдельных слов, блок про trade-off |
| Шэдоуинг | артикуляция ставится только артикуляцией | блоки для проговаривания вслух с разметкой пауз |
| Чередование | вперемешку материал удерживается дольше | карточки перемешиваются между темами |
| Желательная трудность | лёгкая тренировка даёт ложную уверенность | таймер, скрытый эталон, открытые вопросы вместо выбора |
| Элаборация | объяснение своими словами углубляет понимание | задания «объясните нетехническому человеку», уточняющие вопросы |
| Метапознание | важно знать границу своего знания | честная самооценка ответа, разбор «как признать незнание» |

Чего здесь сознательно нет: «стилей обучения» (визуал, аудиал, кинестетик),
тренировки «полушарий» и прочих популярных идей, не подтверждённых
исследованиями. Тип упражнения в интерфейсе подписан приёмом, на котором оно
построено, — чтобы было видно, зачем вы его делаете.

## Установка

Требуется PHP 8.3+, Composer и Node.js 20+.

```sh
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate --seed     # создаст схему и загрузит банк вопросов
npm install && npm run build
php artisan serve
```

Приложение будет доступно на http://localhost:8000. По умолчанию используется SQLite;
для MySQL или PostgreSQL достаточно изменить `DB_*` в `.env`.

## Публичный доступ через ngrok

Чтобы показать тренажёр коллеге или открыть его с телефона, приложение можно
выставить наружу туннелем. Понадобится [аккаунт ngrok](https://dashboard.ngrok.com)
и его authtoken — без него агент не запустится.

```sh
# 1. Один раз: установить агент и записать токен
#    (macOS: brew install ngrok, Linux: пакет с ngrok.com/download)
ngrok config add-authtoken <ваш_токен>

# 2. Разрешить приложению доверять заголовкам туннеля
echo 'TRUSTED_PROXIES=*' >> .env
php artisan config:clear

# 3. В одном терминале — приложение, в другом — туннель
php artisan serve
ngrok http 8000
```

ngrok выдаст адрес вида `https://xxxx.ngrok-free.app` — он и есть публичная ссылка.

Что важно не пропустить:

- **`TRUSTED_PROXIES=*` обязателен.** Без него Laravel считает соединение
  незашифрованным и строит ссылки на `http://localhost`: ломаются стили,
  формы и редиректы. Значение `*` уместно именно для туннеля с плавающим
  адресом; за собственным балансировщиком укажите список его IP через запятую.
- **Соберите фронтенд:** `npm run build`. Режим `npm run dev` отдаёт ассеты с
  localhost — снаружи они не загрузятся.
- **Выключите отладку:** в `.env` поставьте `APP_DEBUG=false` и
  `APP_ENV=production`. Иначе при любой ошибке посетитель увидит стектрейс
  с содержимым конфигурации.
- **Ссылка публичная.** В тренажёре нет авторизации: любой, кто знает адрес,
  откроет его и создаст свой профиль. Для закрытого показа добавьте
  `ngrok http 8000 --basic-auth "user:пароль"`.
- Туннель живёт, пока запущены обе команды; на бесплатном тарифе адрес
  меняется при каждом перезапуске, и первый заход показывает предупреждение
  ngrok.

Так же работает любой другой туннель — например `cloudflared tunnel --url http://localhost:8000`,
требования к `TRUSTED_PROXIES` и сборке ассетов те же.

## Тренировка в терминале

```sh
php artisan interview:drill --topic=laravel-core --level=middle --count=5
```

Команда задаёт вопросы, показывает эталон после вашего ответа и записывает самооценку
в ту же очередь повторений, что и веб-интерфейс. Список тем — колонка `slug` в таблице `topics`.

## Разработка

```sh
php artisan test          # 85 тестов: сценарии, оценка, повторения, переводы, контент банка
./vendor/bin/pint         # стиль кода
npm run dev               # Vite с горячей перезагрузкой
```

## Как добавить свои вопросы

Банк вопросов — это JSON-файлы в `database/data/questions/`, по файлу на тему,
а переводы — в `database/data/translations/<язык>/`.
Добавьте вопрос в массив `questions` и выполните `php artisan db:seed`:
сидер идемпотентен и обновляет существующие записи по полю `id`.

```json
{
  "id": "laravel-core-17",
  "type": "theory",
  "difficulty": "middle",
  "estimated_seconds": 120,
  "prompt": "Чем отличается bind от singleton?",
  "answer": "Эталонный ответ, который увидит кандидат.",
  "explanation": "Необязательный комментарий и типичные ошибки.",
  "follow_ups": ["Что такое scoped?"],
  "checklist": ["Называет разницу в жизненном цикле"],
  "red_flags": ["Путает контейнер с фасадом"],
  "tags": ["контейнер"]
}
```

Поддерживаемые `type`: `theory`, `quiz` (нужны `options` и `correct_option` — индекс с нуля),
`coding`, `behavioral`, `system_design`, `cloze` (нужен `accepted` — список допустимых
ответов) и `shadowing` (в `answer` лежит образец для проговаривания).
Уровни: `junior`, `middle`, `senior`.

Перевод вопроса — запись в файле языка, где ключ совпадает с `id` вопроса;
незаполненные поля берутся из оригинала, так что можно перевести только формулировку:

```json
{
  "locale": "en",
  "questions": {
    "laravel-core-17": {
      "prompt": "What is the difference between bind and singleton?",
      "answer": "bind resolves a new instance every time, singleton caches one per request."
    }
  }
}
```

У вопросов с вариантами ответа порядок `options` в переводе обязан совпадать с
оригиналом — иначе правильный ответ съедет; это проверяется тестом.
Структура файлов проверяется тестом `QuestionBankSeederTest`, так что опечатка в поле
или дубль идентификатора уронят CI.

## Структура кода

```
app/
├── Console/Commands/DrillCommand.php   тренировка в терминале
├── Enums/                              типы вопросов, уровни, режимы, язык, самооценка
├── Http/Controllers/                   дашборд, сессии, банк вопросов, прогресс
├── Http/Middleware/IdentifyTrainee.php профиль кандидата в сессии браузера
├── Models/                             Topic, Question, QuestionTranslation, Trainee,
│                                       InterviewSession, SessionItem, ReviewCard
└── Services/
    ├── InterviewBuilder.php            сборка сценария интервью по фазам
    ├── QuestionBank.php                подбор вопросов, приоритет слабых тем
    ├── SessionGrader.php               приём ответа, оценка, закрытие сессии
    ├── SpacedRepetition.php            планировщик повторений (SM-2)
    └── ProgressReport.php              статистика, готовность, рекомендации
app/Support/                            склонения, сверка ответов, локализованный текст
database/data/questions/                банк вопросов в JSON
database/data/translations/en/          английские версии вопросов
```
